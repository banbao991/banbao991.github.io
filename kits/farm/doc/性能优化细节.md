## 当前实测摘要（2026-10-10）

累计14项已验证本地优化。前13项同环境晴天全图暂停的同帧绘制 **20.59→3.55 ms（减少82.8%）**，独立单绘制 **18.62→3.47 ms、42.47→108.77 FPS**。新增第14项改善移动镜头：拖动 **9.62→8.34 ms**、缩放 **9.55→8.21 ms**，约减少13%–14%，固定全图视角基本不变；独立拖动FPS未改善。画面、完整状态与玩法保持，本项100组PNG/完整状态对照及原始固定图一致。完整条件、P95/峰值与限制见下文，默认档保留。按用户最新要求只继续有明显收益的方向，最后候选已评估且未采用，每小时续作已停止；微优化不再延续监测。

## 目标与一致性要求

2026-10-10用户明确：**主要评估总耗时，FPS不作为采用优化的门槛**。后续优先比较同环境整帧脚本与绘制耗时的平均值、P95，峰值作辅助；FPS保留记录，但受requestAnimationFrame调度影响，保持不变不否定稳定的CPU收益。已有报告的实测FPS与耗时均保留，不改写历史数据。用户「明显收益」要求继续有效，避免为了微小收益增加架构复杂度。

基于 v1.2 优化，保留全部对象、玩法、世界状态、交互、渲染顺序、完整存档及动画。不能用缩减内容、降低画布分辨率或降低动画频率代替优化。世界绘制只读；缓存只属于美术层，不写入存档。

普通截图允许暂停原地动作的相位差；严格验证使用同一存档、同一动画时钟、同一视角、同一画布尺寸，逐像素比较。季节、天气、施工、导入、缩放、拖动和完整地图导出均需检查缓存有效性。

## 优化思路与次序

1. 细分地面、场景收集、实体绘制与天气耗时，保留优化前代码供隔离对比。
2. 缓存不变地面，预计算固定草纹与水岸图案；季节颜色或实际镜头改变才重建。
3. 整理重复排序及重复计算，维持稳定的同键登记顺序。
4. 根据实际剩余热点，再考虑建筑树木分体缓存和视野裁剪；全图场景裁剪收益有限。

## 2026-10-10 · 第一轮：基础地面视窗缓存（已验证）

### 核心思路

完整地图每帧都要给约 19200 个地形格计算 RGB、分组填充，并为固定草纹重复计算散列。镜头和季节颜色没有变化时，这些像素完全相同。因此只保存基础草地、渐变、固定草纹和地表小花；其他内容沿用原流程。

- `js/art/terrain-cache.js` 保存一张与主画布内部尺寸相同的离屏画布。重建时仍调用原 `groundTilePainter()` 与 `terrainDetails()`，使用完全相同的镜头变换和像素对齐规则。
- 命中时在屏幕原点按 **1:1** 复制。不是先画世界纹理再缩小，避免改变缩放抗锯齿、道路接缝或边缘细节。
- 缓存键包括内部宽高、镜头 x/y/zoom、实际变换矩阵，以及基础地面使用的全部已解析颜色。季节逐渐交替时，实际 RGB 变化才重建；不冻结季节过渡。
- 河湖、水纹、湿地湿度、杂草、道路、建筑、作物、角色、动物、飞行物与天气保持逐帧绘制。施工、清理、人物移动、欢庆和天气逻辑没有调整。
- 完整地图导出的独立上下文直接使用原画法；不创建第二张缓存、不污染主视窗。绘制异常恢复 `ctx` 并清空有效键，避免把未完成的栅格当成命中。
- 只保留一个尺寸的栅格，不累积多个镜头或多个季节纹理。1152 × 816 的 RGBA 数据约 **3.59 MiB**；浏览器可能另有纹理开销。缓存不进入 `farm`、运行快照或存档。

### 公平计时与收益

实际浏览器使用 v1.2 默认第 742 天存档，Canvas 内部 1152 × 816、完整地图 42.5%，CSS 显示 **1410 × 998.75**。与用户截图高度相差 0.60 CSS 像素，内部绘制尺寸一致。页面屏蔽玩家缓存读写，Debug 卡片收起。

隔离页面的多轮独立 12 秒采样波动较大：优化前暂停绘制均值为 20.25–37.97 ms，优化后为 9.13–10.48 ms。不能把不同负载下的极端结果相减；最早未充分预热的窗口不作为收益基准。

为减少负载变化的影响，补充 **同一帧交替绘制**：同一世界状态、同一动画时钟，分别走直接绘制和缓存；每帧轮换先后顺序，12 秒采样，丢弃最初 20 对。下面是暂停全图的 369 对有效样本：

| 地图 CPU 绘制指标 | 直接绘制 | 地面缓存 | 减少 |
| --- | ---: | ---: | ---: |
| 平均 | 20.07 ms | 9.02 ms | 55.0% |
| P95 | 20.90 ms | 9.50 ms | 54.5% |
| 最慢样本 | 28.60 ms | 11.90 ms | 58.4% |

正常运行再采样 329 对，平均 **20.25 → 9.20 ms（减少 54.6%）**，P95 **21.30 → 9.80 ms**，最大 **28.10 → 16.50 ms**。每对绘制之间不推进模拟，两个路径看到完全相同的角色、作物和天气状态；模拟仍在正常主循环中按原规则运行。

同帧对比使用当前原图元的直接绘制路径；另保留修改前的绘制文件，做完整基线页面与 PNG 对照。计时覆盖地面、实体收集/排序、实体与天气，**不含模拟、浏览器合成和 GPU 提交后耗时**。同帧测试每次绘制两遍，不能用它的帧率代表正常运行 FPS。

独立窗口观察到优化前 25.1–41.5 FPS、优化后 88.5–99.9 FPS，但浏览器刷新调度和主机负载波动很大，只作为本次环境的观察结果。用户原来的 49 FPS 不能直接换算为优化后的固定 FPS；应在原设备原页面用 Debug 卡片复核。

### 一致性与实际验证

- 修改前、修改后独立页面加载同一存档，以 `now=200`、`motionNow=100` 固定动画时钟：1152 × 816 PNG **逐像素差异 0，最大通道差 0**。
- 13 种额外场景，每种分别验证缓存重建、命中及重复直接绘制，共 39 组对照，差异全部为 0：晴天、夜景、雨、冬季雪、三段季节交替颜色与另一日期、分数镜头拖动/缩放、初始地图、1536 × 864 宽视窗、864 × 1200 高视窗，以及 2560 × 1920 独立全图导出上下文。
- PNG 在原画布上直接冻结，另用只读回读画布解码比较。早期反复对主画布 `getImageData()` 会使 Chromium 切换 GPU/CPU 绘图后端，造成对比过程本身的抗锯齿差异；该方式已替换，并保留重复直接绘制作为验证器的自检。
- `node kits/farm/tests/smoke.cjs` 完整通过；该 harness 的简化 Canvas 会走缓存回退路径。另有 `node kits/farm/tests/terrain-cache.cjs` 覆盖真实缓存命中、颜色/镜头/矩阵/尺寸失效、失败恢复、导出隔离和世界状态不含缓存。
- 实际浏览器控制台没有错误；正式默认 ZIP、存档格式、角色行为与玩家缓存未改动。

### 复现工具

`node kits/farm/scripts/prepare-performance-qa.cjs` **在修改绘制代码之前**准备一次基线快照，然后通过现有本地服务打开 `/kits/farm/.qa-performance/before.html` 和 `after.html`。支持第二个参数指定已保留的基线源码目录；已有快照不覆盖。`.qa-performance/` 是忽略的本地临时目录，验收后可删除。

`tests/performance-qa.js` 只由验证页面加载，不进入首页。提供暂停/运行/夜/雨/雪准备、12 秒计时、同帧交替计时、固定时钟 PNG 和缓存一致性检查；不读写玩家缓存。

本轮修改前绘制源码来自 Git 基线 `5ed6f500b96f2c7219a83efbe598425b89d41dac`。复测不要把已优化文件误当成原版。第一轮快照包含五个涉及的绘制文件，第二轮增加 `east/east-shore-art.js`；其他游戏脚本共享当前版本。新增优化涉及其他文件时，应扩充快照清单。

### 限制与下一轮

- 拖动、缩放、尺寸变化、实际地表颜色变化的帧仍需重建，不能承诺这些帧也获得同样收益；当前单张缓存主要改善镜头稳定时的绘制。
- 剩余热点：东缘林泉/小塘每帧重复生成水岸几何与颜色，湖底与河岸等固定遮罩也可预计算。下一轮优先将静态几何与动态水纹分开，保留原填充顺序和世界坐标。
- 实体队列确实有重复排序，但应先测它的单独成本再决定是否改动。建筑/树木分体缓存和视野裁剪排在后面，全图场景不会因裁剪获益。
- 后续每轮沿用相同存档、固定时钟像素检查和同帧交替计时，不以减少动画、对象或画布尺寸作为收益。

## 第二轮：东岸水岸几何与颜色分组复用（2026-10-10，已验证）

### 成本与方案

第一轮缓存保持启用，v1.2 第 742 天、晴天、暂停、全图、内部 1152 × 816、显示 1410 × 998.75、缩放 0.425。12 秒分项采样中，林泉/小塘水面平均 0.845 ms，占整图 7.822 ms 的约 10.8%。`eastShore` 是 `ground` 的子项，不能重复相加。

`art/east/east-shore-ground.js` 按共享椭圆坐标惰性生成原 4 像素水岸格子，保留原行列次序、透明度精度和颜色分组顺序。每帧只计算四种实际颜色，颜色相同就复用原 `groundTilePainter()`；岸先水后、水纹随后绘制。水纹、泉眼、点击涟漪、动物、天气、暂停动画与渲染层级均保持。此处没有新增栅格纹理或改变画布分辨率。

失效与范围：

- `site.x/y/rx/ry` 变化时重建该水体几何与分组。
- 三种水色或岸边 RGB 实际变化时重建分组，连续季节权重未改变整数颜色时直接复用；每处只保留最后一套颜色。
- 拖动、缩放、尺寸变化及独立 PNG 导出不复用屏幕像素；原 painter 每次按当前上下文/变换对齐格子，因此保持接缝规则。
- 使用 WeakMap，缓存属于绘制模块；不写 `farm`、不消耗随机流、不修改模拟或 JSON/ZIP。首次及颜色变化帧仍需计算，稳态收益不能套用到这些帧。

### 实测收益

同一帧交替旧水岸/新水岸，两个画法都启用第一轮地面缓存，预热 20 对。两种顺序逐帧交换，12 秒窗口；双绘制的 FPS 不作为产品 FPS。

| 场景 | 有效配对 | 整图均值旧 → 新 | P95 旧 → 新 | 峰值旧 → 新 | 均值下降 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 暂停 | 742 | 7.661 → 7.264 ms | 8.30 → 7.90 ms | 15.70 → 19.80 ms | 5.2% |
| 运行 | 626 | 7.810 → 7.298 ms | 8.50 → 7.90 ms | 16.30 → 13.90 ms | 6.6% |

独立普通绘制 12 秒窗口：均值 7.822 → 7.391 ms，P95 8.90 → 8.30 ms，峰值 14.80 → 14.70 ms；水面子项 0.845 → 0.404 ms。FPS 为 **104.91 → 101.99**，这两段独立窗口未体现 FPS 提升，说明调度和主机负载仍有波动；不将 CPU 毫秒倒数写成产品帧率，也不承诺峰值改善。相对本轮基线，同帧 CPU 下降才是保留本项的依据；不把此轮环境绝对毫秒与上一轮叠加作累计收益。

### 一致性与复现

- 14 种固定时钟场景 × 重建/命中/旧画法自检，共 **42 组 PNG 像素差异全为 0**。包括成熟/初始地图、晴/夜/雨/雪、连续季节颜色（含第 760 天冬季过渡）、分数镜头、宽/高画布、完整导出。
- 独立保存的第二轮结果 PNG 与最初第一轮优化前 PNG 比较：1152 × 816、变化像素 0、最大通道差 0，验证两轮累积后的图像一致性。
- `east-shore-ground.cjs` 通过：缓存复用、量化相同颜色不重建、四项坐标变化全部失效、岸先水后、当前导出上下文。完整 `smoke.cjs` 通过，语法及 `git diff --check` 通过。
- 正式默认存档和玩家缓存保留。
- 清理临时目录后复现第二轮，请运行 `node kits/farm/scripts/prepare-performance-qa.cjs <修改前源码目录>`，避免用当前已优化水岸当旧版。脚本从旧快照生成只在 QA 页加载的原水岸函数；界面选择「东岸水面几何」。选择「基础地表缓存」仍可对照第一项。测试工具不进入正式首页。

### 下一候选

本项完成。剩余地面约 3.4 ms，队列收集约 1.9 ms、实体绘制约 2.0 ms；优先继续拆分这几个阶段的成本。固定湖底/河岸遮罩及重复队列计算仍有检查价值，先计时再实现。原 `drawPond()` 只有约 0.075 ms，暂不优先优化；保留全部水面和动画。监测继续启用。

## 第三轮：村口与广场地面分组复用（2026-10-10，已验证）

### 测量与选择

先核对第二轮代码、原始结果和已完成测试；5 小时额度剩余 71%、周额度剩余 55%，没有其他开发回合。继续使用 v1.2 第 742 天默认档、晴天 10:35、暂停、全图，内部 1152 × 816、显示 1410 × 998.75、缩放 0.425；前两轮优化在所有对照中保持启用。

增加地面、道路和排序细项后，村口/广场地面平均 **2.953 ms**，湿地底色 1.298 ms、道路表面 1.475 ms、两次排序合计 0.182 ms。地面与队列收集是这些子项的父项，不能重复相加。优先复用成本最高的村口/广场地面；排序暂不改动。

本轮主机负载明显高于第二轮：独立整图均值约 14.62 ms，对应约 51 FPS。收益使用本轮同环境、同帧交替计时，不把跨轮绝对毫秒相减，不把双绘制 FPS 当产品 FPS。

### 实现与失效规则

`art/village/village-ground.js` 分开保留院落与广场的原 `groundTilePainter()` 分组，删除每帧重复的格子判断、散列、透明度格式化和分组构造。保持原行列顺序、颜色、透明度字符串、像素对齐与叠加顺序；115 处碎粒保留原浮点坐标，仍按原 `rect()` 绘制。只缓存几何和分组，不新增栅格图片。

- 院落键包含街区四条边、小屋/摊位实际参与地面计算的横坐标、喷泉坐标、两个摊位开放状态。市场升级或矿区开放会重建对应院落，不预先画未开放的矿摊地面。
- 广场键包含四条边界；原 `plazaRightAt()` 斜边仍参与几何生成。每帧先检查广场工程，未完工时不绘制广场，也不提前生成它的缓存。
- 加载不同世界、重新开始、施工完成读取当前开放条件；不根据上次世界的完工状态决定可见性。
- 镜头、尺寸、独立导出使用当前上下文和原对齐逻辑。颜色固定，不受季节切换影响；每个区域只保留最近一份分组。不缓存人物、家具、水流、建筑、灯光或世界状态，不改模拟及存档。
- 初次绘制、开放状态变化或共享坐标变化需重建，稳态耗时不代表这些帧。

### 实测收益

12 秒同帧交替测量，逐帧交换顺序、预热 20 对：

| 场景 | 有效配对 | 整图均值旧 → 新 | P95 旧 → 新 | 峰值旧 → 新 | 均值下降 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 暂停 | 401 | 14.283 → 12.763 ms | 15.20 → 13.80 ms | 25.70 → 20.90 ms | 10.6% |
| 运行 | 315 | 14.443 → 12.938 ms | 15.50 → 13.80 ms | 28.50 → 26.50 ms | 10.4% |

固定镜头已有整张基础地面缓存，通常约3.5ms；此前小项没有稳定提高FPS。拖动或缩放会使栅格缓存失效，原画法给每个可见地形格重新计算三通道并拼接RGB。`region-ground.js` 增加一份最近实际七色调色板的颜色数组，按可见格惰性填充；镜头移动复用相同格的准确颜色。键包含全部实际通道值和原颜色计算函数引用，不量化季节、不缓存新一天的世界状态。

`groundCells` 是该文件初始化一次的固定地形，生产代码没有修改入口；若未来允许编辑地形，应新增地形修订失效。当前每次仍读取视角、原视野范围，按原顺序创建地面分组并在当前变换下重建栅格，草纹/地表花纹保持原调用；不能用拉伸世界图片替代。跨季节实际颜色变化只保留一份新数组，最多19200格，不随拖动累积缓存。完整导出也使用同一纯颜色结果，几何、分数像素对齐、绘制上下文和存档语义不变。

### 判断与实际验证
