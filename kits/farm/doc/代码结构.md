# 苔谷农场：代码结构

[设计与协作约定](../README.md) · [世界与玩法](世界与玩法.md) · [运行逻辑](运行逻辑.md)

本文记录现有模块。v1.2 施工系统与统一存档转换已接入；完整建设规则见 [村庄发展](村庄发展.md)。

## 模块边界

页面使用按顺序加载的普通 JavaScript 脚本，所有脚本均启用严格模式。这样直接打开 `file://` 页面也能游玩，不需要构建工具、模块服务器或联网依赖。现阶段函数与状态共享页面作用域，文件划分负责表达职责，不能把文件拆分理解为独立模块作用域。城镇扩展的多文件分别归入 `core/town/`、`life/town/`、`art/town/` 与 `ui/town/`，层级职责保持一致，避免各层目录堆积同一功能的文件。

| 目录 | 负责 | 修改时的边界 |
| --- | --- | --- |
| `js/core/` | 配置、共享坐标、持久状态、存档、日历、经济、演变调度 | 不放具体居民的通勤和绘制代码 |
| `js/life/` | 人物和动物的状态、日常行为、采集、移动、命中与活动描述 | 角色自己接入欢庆规则；不要把平日行为塞进欢庆模块 |
| `js/art/` | 像素绘制、视觉过渡、遮挡与场景组合 | 读取行为模块的位置；不推进工作、货运、鱼点或角色路线 |
| `js/ui/` | 界面、输入、检查文字、视角、导入导出与启动 | 调用世界行为，界面刷新不能代替世界演变 |
| `css/` | 公共样式、各界面组件与响应式覆盖 | 通用样式先加载，响应式覆盖最后加载 |
| `saves/` | 各发布版本的默认 ZIP 与直接打开页面所需的数据副本 | ZIP 是来源；更新后用打包脚本生成副本，不手改编码数据 |
| `logs/` | 各版本变化汇总与发布记录 | 描述相对于开发基线的最终变化，标明本地开发或正式发布状态 |
| `doc/history/` | 按开发基线分档的完整过程记录 | 保存实现、验证、默认选择与续作点；新基线使用新文件，当前入口由记录索引维护 |
| `scripts/` | 成熟默认农场的离线演变与数据打包工具 | 只生成分发资产，不参与网页运行；演变使用首页实际脚本和隔离测试环境 |

共用的地形、树木和建筑坐标集中在 `world-layout.js`。绘制、命中、小地图与遮挡应复用这些坐标。保存格式与运行状态字段维持原有语义，整理文件时不重命名存档字段。

当前默认农场在 `saves/v1.2/`，原 `saves/v1.0/` 保留。HTTP 页面读取 ZIP；直接打开 `file://` 页面时，读取同目录 `default-save.js` 中同一 ZIP 的编码副本，避免本地文件读取限制。副本通过 `node kits/farm/scripts/bundle-default-save.cjs 1.2` 生成，校验它与 ZIP 逐字节一致。首页脚本选择版本，按钮和日期读取同一份 `DEFAULT_FARM_SAVE` 元数据。

`node kits/farm/scripts/generate-default-save.cjs 1.2` 在隔离环境从真实 120 金的新农场推进全部行为，待大型工程、迁入、苗圃、六类三级改善与永久物品成熟后生成完整 ZIP；不读写玩家缓存，不直接设置金币或解锁。该工具加载测试 harness 提供的 DOM/画布桩，世界规则仍来自首页实际脚本；不会覆盖目录里已有的发布 ZIP。生成后再运行上述打包命令同步本地副本。再次生成须先另行保留已有 ZIP，不手改编码数据。

## 核心 `js/core/`

| 文件 | 职责 |
| --- | --- |
| `world-layout.js` | 河流、湖泊、道路、桥、广场、建筑、北岭活动点、猫头鹰落脚树与各区域树木坐标；共用地形命中和湿地几何 |
| `utils.js` | 确定性散列、随机区间、数值限制、距离和颜色插值；没有角色或存档初始化 |
| `config.js` | 世界尺寸、时间参数、季节色板、作物目录、货物类型、建设与苗圃门槛 |
| `town/town-layout.js` | 东岸驿屋、货车、茶桌、巢箱和公共设施的共享坐标 |
| `town/town-config.js` | 财富阶段、商品、预算模式和公共设施目录 |
| `town/town-state.js` | `farm.town` 工厂和导入校验；完整保存商人、预算、见闻、茶会与鸟蝶状态 |
| `town/town-economy.js` | 城镇随机种子、经营储备、季节预算、实际采购结算与每日来访准备 |
| `state.js` | 初始农场及区域数据工厂、田地布局整理、当前 `farm` 和演变时钟 |
| `storage.js` | 存档解析校验、浏览器缓存读取与自动保存；保留原来的缓存键与完整状态格式 |
| `archive-codec.js` | ZIP 打包、按文件内容识别容器、解压及压缩包成员/体积检查；只返回 JSON 文本，不替换世界状态 |
| `calendar.js` | 日期、季节、天气、昼夜显示与跨日更新；季节和天气连续过渡 |
| `festival-budget.js` | 欢庆预算参数的计算、清晨一次结算、规模与日程描述；保存累计支出，绘制和界面不扣款 |
| `economy.js` | 订单生成、农场日记记录、种植选择与建设解锁 |
| `simulation.js` | `updateActors` 的固定更新顺序；角色行为的唯一集中调度入口 |
| `runtime-snapshot.js` | 所有人物、动物、工具、路线与动画时钟的完整捕获、校验和恢复 |

`state.js` 读取缓存前，配置、工具、存档解析和订单工厂必须已定义。`storage.js` 定义函数时不初始化角色；运行状态恢复要等所有角色定义之后执行。

| `ui/development/resident-roster.js` | 稳定居民按钮、12 帧每秒的小像刷新、动态详情提示、键盘聚焦与点击定位；暂停仍更新显示动画 |

## 加载与执行顺序

ZIP 使用站点根目录下的 `libs/fflate@0.8.3/fflate.min.js`，固定版本、许可证及来源说明随库保存。浏览器从本地资源加载，支持离线与 `file://`；库必须先于 `archive-codec.js` 加载。

`index.html` 是唯一的页面脚本清单。使用 `defer` 让脚本在 DOM 解析完后按声明顺序执行。冒烟测试直接读取这个清单，不再维护第二份文件列表。

1. 共享布局、数学工具、配置、DOM、存档与经济函数。
2. 创建/读取农场，定义日历、共用欢庆规则及各角色行为。
3. 定义行为调度与完整运行状态快照。
4. 定义绘制上下文、视角、小地图与各场景绘制。
5. 定义卡片刷新、检查文字、输入事件、存档与纯享功能。
6. 最后执行 `ui/app.js`：恢复缓存中的运行状态、同步工具与界面、启动动画循环。

动画循环分别维护真实动画时钟 `now` 与未暂停时推进的世界动作时钟 `motionNow`。未暂停时推进农场时间并调用 `updateActors`；暂停时仍刷新悬停、绘制天气与原地动作，角色路线和工作不前进。

新增文件要在首页按依赖关系加载。允许函数引用后面定义的函数，但不能在文件顶层提前调用尚未加载的模块。新增顶层名称也要检查是否与已有名称冲突。

## 城镇状态与续作

城镇新增对象集中保存于 `farm.town`，包含移动中的阿棠和鸟蝶，因此不再在 `runtime` 重复保存同一份对象。旧版演员仍由 `runtime-snapshot.js` 捕获；两部分一起导出。阿宁本人位置继续在 `runtime.villageWalker`，阿宁的茶会路线和阶段在 `farm.town.childVisit`，必须同时恢复。邻里茶会同样将阿葵的实际位置保留在 `runtime.orderKeeper`，邀请与客人路线在 `farm.town.teaParty`，不重复保存演员。猫咪玩耍进度与球放在 `farm.town.catPlay`，两只猫仍在 `runtime.plazaCats`。首页读取浏览器缓存前加载城镇配置和数据工厂，存档解析仅在缺少 `town` 时补默认值。

世界向东扩为 2560 × 1920，既有区域、河流和居民小屋保持原坐标。新道路、命中、小地图、完整 PNG 与摄像机共用新尺寸。这轮功能实现与验证见 [基于 v1.0 的开发历史](history/持续开发记录-v1.0.md)，后续工作从 [记录索引](持续开发记录.md) 进入当前文件。
