# 苔谷农场：代码结构

[设计与协作约定](../README.md) · [世界与玩法](世界与玩法.md) · [运行逻辑](运行逻辑.md)

## 模块边界

页面使用按顺序加载的普通 JavaScript 脚本，所有脚本均启用严格模式。这样直接打开 `file://` 页面也能游玩，不需要构建工具、模块服务器或联网依赖。现阶段函数与状态共享页面作用域，文件划分负责表达职责，不能把文件拆分理解为独立模块作用域。

| 目录 | 负责 | 修改时的边界 |
| --- | --- | --- |
| `js/core/` | 配置、共享坐标、持久状态、存档、日历、经济、演变调度 | 不放具体居民的通勤和绘制代码 |
| `js/life/` | 人物和动物的状态、日常行为、采集、移动、命中与活动描述 | 角色自己接入欢庆规则；不要把平日行为塞进欢庆模块 |
| `js/art/` | 像素绘制、视觉过渡、遮挡与场景组合 | 读取行为模块的位置；不推进工作、货运、鱼点或角色路线 |
| `js/ui/` | 界面、输入、检查文字、视角、导入导出与启动 | 调用世界行为，界面刷新不能代替世界演变 |
| `css/` | 公共样式、各界面组件与响应式覆盖 | 通用样式先加载，响应式覆盖最后加载 |
| `saves/` | 各发布版本的默认 ZIP 与直接打开页面所需的数据副本 | ZIP 是来源；更新后用打包脚本生成副本，不手改编码数据 |
| `logs/` | 各版本发布记录 | 记录发布范围、默认存档及后续版本变化 |
| `scripts/` | 默认存档的数据打包工具 | 只生成分发资产，不参与农场运行 |

共用的地形、树木和建筑坐标集中在 `world-layout.js`。绘制、命中、小地图与遮挡应复用这些坐标。保存格式与运行状态字段维持原有语义，整理文件时不重命名存档字段。

v1.0 默认存档在 `saves/v1.0/`。HTTP 页面读取原始 ZIP；直接打开 `file://` 页面时，读取 `default-save.js` 中同一 ZIP 的编码副本，避免本地文件读取限制。副本通过 `node kits/farm/scripts/bundle-default-save.cjs 1.0` 生成，测试会检查它与 ZIP 逐字节一致。新版本可在 `saves/v<版本>/` 放入唯一一份 ZIP，再传入相应版本生成副本，并更新首页的脚本路径与入口文字。

## 核心 `js/core/`

| 文件 | 职责 |
| --- | --- |
| `world-layout.js` | 河流、湖泊、道路、桥、广场、建筑、北岭活动点、猫头鹰落脚树与各区域树木坐标；共用地形命中和湿地几何 |
| `utils.js` | 确定性散列、随机区间、数值限制、距离和颜色插值；没有角色或存档初始化 |
| `config.js` | 世界尺寸、时间参数、季节色板、作物目录、货物类型、建设与苗圃门槛 |
| `state.js` | 初始农场及区域数据工厂、田地布局整理、当前 `farm` 和演变时钟 |
| `storage.js` | 存档解析校验、浏览器缓存读取与自动保存；保留原来的缓存键与完整状态格式 |
| `archive-codec.js` | ZIP 打包、按文件内容识别容器、解压及压缩包成员/体积检查；只返回 JSON 文本，不替换世界状态 |
| `calendar.js` | 日期、季节、天气、昼夜显示与跨日更新；季节和天气连续过渡 |
| `festival-budget.js` | 欢庆预算参数的计算、清晨一次结算、规模与日程描述；保存累计支出，绘制和界面不扣款 |
| `economy.js` | 订单生成、农场日记记录、种植选择与建设解锁 |
| `simulation.js` | `updateActors` 的固定更新顺序；角色行为的唯一集中调度入口 |
| `runtime-snapshot.js` | 所有人物、动物、工具、路线与动画时钟的完整捕获、校验和恢复 |

`state.js` 读取缓存前，配置、工具、存档解析和订单工厂必须已定义。`storage.js` 定义函数时不初始化角色；运行状态恢复要等所有角色定义之后执行。

## 世界行为 `js/life/`

| 文件 | 职责 |
| --- | --- |
| `farm-workers.js` | 主场四名农务伙伴与阿栀、阿牧的角色状态、职责、任务分配、连续工作、移动、返家、欢庆接入、问候与命中 |
| `farm-animals.js` | 牛、鸡、羊的状态和移动；主场池塘小鸭的位置及命中 |
| `festival-life.js` | 十日一次的判定、四季主题、聚会路线、赴会与返家流程、欢庆后清晨出门、活动描述和在家判定；不拥有居民实例或平日通勤 |
| `festival-activities.js` | 广场活动点预留、取餐/聊天/观看/休息/跳舞/演奏、避开家具的短路线、四人移动上限及居民活动描述 |
| `angler-life.js` | 阿蓼的状态、栈桥与小屋通勤、欢庆接入、每日限量垂钓、进度、位置、可见性、命中和活动描述 |
| `order-keeper.js` | 阿葵的状态、集市北侧通勤、移动、欢庆接入与命中；普通工作调用东岸菜圃模块 |
| `east-garden.js` | 东岸 28 畦独立蔬菜轮作、村口菜篮、日常消耗及阿葵的照料任务和动作；不进入农场订单与货运 |
| `forest-keeper.js` | 阿森的晨间选择、逐朵采菇、动物观察、干地寻路、返家与活动描述 |
| `village-life.js` | 阿宁的散步、返家、欢庆接入、位置与命中 |
| `logistics.js` | 六处货箱、货值、阿运的收货和送货、夜间休息、路线计划与活动描述；路线在返程出发时确定，到箱后取走全部现货 |
| `mine-life.js` | 矿脉再生、阿矿的连续开采、每四天一趟的独立送矿、茶亭休息、双桥返家与命中 |
| `nursery-life.js` | 湿地苗床修复、逐畦培育、水位、青蛙，以及阿芽的连续采收、休息、返家和活动描述 |
| `valley-gardens.js` | 山谷香草生长、采摘与阿栀的休息和夜间路径 |
| `meadow-life.js` | 山羊状态、牧场内活动、互动与命中 |
| `wildlife.js` | 林间采集点、松鼠的状态与行为、狐狸的位置和命中 |
| `ridge-life.js` | 北岭鹿、野兔、猫头鹰的状态、觅食、巡飞、落脚与互动；位置定义复用共享布局 |
| `lake.js` | 西湖有限鱼点、钓获结算、水鸭的状态与互动 |
| `valley-life.js` | 西南小湖的水獭、乌龟、苍鹭、小鱼群与互动 |
| `plaza-life.js` | 两只广场猫与麻雀的日程、避开家具的路径、避雨返屋、猫鸟与居民互动、位置和命中 |
| `wetland-life.js` | 湿地黑水鸡、蜻蜓、萤火虫和水生植物的昼夜、天气、命中与互动 |

一个角色的状态创建、平日调度和欢庆接入应能从该角色所属的行为模块定位。共享欢庆引擎接收角色、家、路线和集合位置；到场后调用独立的广场活动模块。预算在清晨和首次恢复未筹备的欢庆日时结算，活动模块只读取预算等级。阿葵的角色生命周期在 `order-keeper.js`，具体菜圃任务仍与菜床规则放在 `east-garden.js`。

## 加载与执行顺序

ZIP 使用站点根目录下的 `libs/fflate@0.8.3/fflate.min.js`，固定版本、许可证及来源说明随库保存。浏览器从本地资源加载，支持离线与 `file://`；库必须先于 `archive-codec.js` 加载。

`index.html` 是唯一的页面脚本清单。使用 `defer` 让脚本在 DOM 解析完后按声明顺序执行。冒烟测试直接读取这个清单，不再维护第二份文件列表。

1. 共享布局、数学工具、配置、DOM、存档与经济函数。
2. 创建/读取农场，定义日历、共用欢庆规则及各角色行为。
3. 定义行为调度与完整运行状态快照。
4. 定义绘制上下文、视角、小地图与各场景绘制。
5. 定义卡片刷新、检查文字、输入事件、存档与纯享功能。
6. 最后执行 `ui/app.js`：恢复缓存中的运行状态、同步工具与界面、启动动画循环。

动画循环分别维护真实动画时钟 `now` 与未暂停时推进的世界动作时钟 `motionNow`。未暂停时推进农场时间并调用 `updateActors`；暂停时仍刷新悬停、绘制天气与原地动作，角色路线和工作不前进。

新增文件要在首页按依赖关系加载。允许函数引用后面定义的函数，但不能在文件顶层提前调用尚未加载的模块。新增顶层名称也要检查是否与已有名称冲突。

## 架构整理后的检查

- `node kits/farm/tests/smoke.cjs`：世界规则、居民通勤/欢庆、货运、动态提示、存档往返、缩放、全屏和完整 PNG。
- 对 `js/` 下所有脚本执行 `node --check`。
- 冒烟测试同时检查所有 JS/CSS 均在首页加载、脚本无重复、关键前置依赖成立、启动脚本与响应式样式最后加载。
- 修改 CSS 时核对桌面、窄屏与纯享模式；结构整理不应改变既有布局、默认展开状态、内部滚轮或现有存档。

可用额外参数验证某份本地存档的完整 ZIP 往返：`node kits/farm/tests/smoke.cjs <存档.json>`；再传第三个参数可把验证过的 ZIP 写到指定输出路径。用户存档不加入仓库。
