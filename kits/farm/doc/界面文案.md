## 给玩家看的内容

地图提示优先写「地点或名字 · 当前状态或场景特色」，必要时再加一句操作提示。侧栏提供库存、进度、价格和活动条件；日记记录真正发生的相遇、收获、建设与花费。文字应像小镇里的介绍，简短、自然，并与画面和当前状态一致。

不要把开发要求、修改历史、文件职责或实现保证拼进这些介绍。尤其避免「留出一格草地」「原修缮行程」「不改变工作与货运」「真正到座才取库存」「第三条向右支线再转向北」等表述。布局、路线和结算约束仍须实现，只是不作为场景介绍。

| 场合 | 推荐写法 |
| --- | --- |
| 休憩角 | 栎树休憩角 · 草坡长椅与野花 |
| 旅人院落 | 旅人院落 · 阿棠和邻居喝茶歇脚的地方 |
| 矿洞 | 河东旧矿洞 · 轨道通向岩坡里的幽深洞口 |
| 居民小屋 | 阿宁的小屋 · 夜里亮起温暖的灯 |
| 活动日记 | 阿宁坐在驿屋茶桌旁，取了一份当季茶点。 |
| 交易条件 | 积蓄 20000 金起，需要两杯花茶；落座后才付点心费。 |

最后一行属于玩家做决定所需的信息，要保留。价格、解锁门槛、库存上限、限购次数、营业时间、免费操作和不能购买的原因不能因为精简而删除。存档覆盖提醒与文件格式选项也应保持明确。方向信息若用于寻找地点可以保留；已经指着一座房子的提示无需再说明它是「第二间」或门朝哪边。

动态状态只描述正在发生的事情。例如安排了施工但尚未开工，与实际施工中的进度应分开；不能让同一条「等阿棠开工」一直显示到完工。主页提供简短的生活与玩法介绍，细则通过原有 Markdown 文档入口阅读。

## 开发约束放在哪里

| 内容 | 记录位置 |
| --- | --- |
| 道路留白、避免重叠、成熟阶段密度 | [README](../README.md)；坐标附近必要的代码注释 |
| 绘制排序、承载物和角色遮挡 | [渲染与遮挡](渲染与遮挡.md) |
| 通勤、天气、停工、库存和付费时机 | [世界与玩法](世界与玩法.md)、[城镇发展](城镇发展.md) |
| 自动委托顺序、保存字段、模块调用 | [代码结构](代码结构.md)、[运行逻辑](运行逻辑.md) |
| 本轮修改、验证和后续选择 | [开发记录索引](持续开发记录.md) 指向的当前记录 |

这次文案整理没有改变上述约束。新增内容应在源头使用合适的玩家文案，避免将实现说明复制到悬停、商品描述、按钮标题和日记里。

## 已有存档中的日记

以前记录的事件可能保存了旧文案。`js/ui/journal-copy.js` 在农场日记和城镇见闻的显示入口替换已知旧短语；只处理这些明确的文字，不按通用关键词删除内容。

原事件、日期、费用、排序、滚动锚点和导出的完整状态保持原样，不迁移或重写玩家存档。新事件直接使用整理后的文案。此模块只负责已有日记的显示，不参与世界演变、结算或保存；不要继续把新文案堆进旧短语表。
