## v1.2 施工与自然阶段

`art/development/development-art.js` 的 `villageSceneItemVisible()` 是主场景队列的统一设施入口，入队和最终绘制均检查；尚未建成的房屋、栈桥、围栏及主人本职演员不能留下提前出现的局部图块。自然植被与施工形态直接使用共享工程/设施占地，清理覆盖实际设施和维护院落，保留外围自然地带。

杂草使用成簇采样：约每 14500 平方像素一个大小不一的椭圆草簇，簇中心在打乱的分区内偏移；每簇尝试 5—11 株，核心偏密，外围偏疏，草根至少相隔 12 像素，夹少量孤立草。四种草丛的大小、朝向与色差固定。未建道路也生成草簇，沿线横向散到邻近草地，不能勾勒出整齐的未来路带；共享路段只交给一个草簇来源，桥面和湿地木板桥不生成陆生杂草。实际路网动态过滤，铺好哪段就清除哪段路面和缓冲内的草，不预先给未建路段留空。

小树沿用分散锚点，约 26000 平方像素一棵、单片最多七棵，候选树间距大于 96 像素，避开已知大树；针叶、圆冠、疏枝树形与大小固定变化，树根为统一排序深度。候选位置只保存在绘制缓存，依据工程 ID 与道路共享坐标确定性生成；现有村民小屋、施工队小屋和建成的邻近建筑也过滤，避免沿路草簇扩到已经居住的房屋里。清理按植被的实际落点查询全部工程与独立设施，不按候选点的生成来源决定土地归属。主场景和小地图每次收集时各生成一次清理遮罩，复用于所有草木；工程施工仍按清场进度逐步清理。渔屋维护院落使用共享范围 x=340…604、y=892…1005，覆盖栈桥、屋侧空地和鱼箱；香草院落 x=638…1220、y=1038…1191，以四周道路内侧为界，包含居所、风车、摇椅、香草田和边缘工作空间。苗床、长椅、驴舍等独立设施也清除其他来源落在其实际占地的草木。水域、苗床恢复和驴舍开放继续使用真实状态过滤。村口东侧覆盖完整驿屋预留区域，院落、茶桌、已购收藏架和已建花园按实际状态清理。不要每帧或每天调用随机数重排植被，也不要将纯美术缓存写入存档。

工程附属清理也读取共享的 `VILLAGE_CLEARING_SITES`：森林门前与货箱、阿牧长椅、湿地观鸟台与货箱、南谷茶桌与座椅、矿石堆场与停车位、旅人小狗休息区。苗床恢复后只清所需侧向通道、行间通道和通往长椅的连接，不提前清空全部未来苗床。猫屋舒适角、巢箱和小驴驿围栏东缘及牌子也按开放状态清理。旅人花园每片扩展按 `level > stage` 判断，长椅从第二级出现；未到等级的花畦继续保留草木。矿区原有地表装饰草也查询同一渐进遮罩，不能绕过工程清理留在轨道和作业区里。

道路和桥面位于地表；未接通桥面的施工木板可逐块出现，但不可提前通行。桥栏、围栏、房屋框架、屋顶、材料与演员使用统一接地点排序；搬家行李附着人物。施工队小屋和阿牧小屋也进入队列。湖边清理包含栈桥与货物落点，避免完工后的树木叠在桥板上。夜间灯光须先检查所属设施开放，不能让未建小屋提前亮灯。

小地图、自然阶段提示和全图导出复用同一状态；绘制不会改付款、进度、路线或每日决定。

## 共用流程

普通地图、纯享模式和完整地图 PNG 都调用 `render()`。地形和行走表面先画，实体共用一次世界坐标排序，飞行物随后绘制，天气光照最后叠加。绘制只读取世界，不改变行为或存档。

`scene-depth.js` 提供 `collectSceneItems()`、`scenePart()`、`sortSceneItems()` 和 `drawSceneItems()`。`render.js` 的 `farmSceneItems()` 组合各区域与角色。收集期间，`scenePart()` 仅登记回调；收集结束后才实际画实体。单独调用区域绘制函数时，`scenePart()` 会直接画，方便预览具体美术。

排序键依次是 `layer`、`y`、`order`。同键保持登记顺序。

### 连续地表与缩放接缝

湖底、河水、草地、湿地渐变、村口院落和矿坡底色使用 `drawing-context.js` 的 `groundTilePainter()`：通过 `add()` 登记原世界矩形，`draw()` 将同色矩形合并到一次填充，按当前镜头变换把相邻色块的共同边界对齐到屏幕像素。不要逐块调用 `fillRect()` 绘制连续水面，否则非整数缩放或拖动会让每块的抗锯齿边缘露出下层地面，形成网格线。

对齐只用于绘制，世界坐标、岸线采样、碰撞和点击遮罩保持原样；完整图片在整数世界坐标下绘制。底色与水纹、石纹等细节分开批次，先完成底色，再叠细节；不能把前后相互遮挡的物体按颜色重新分组。道路继续使用自身的道路并集绘制，施工段不是可见地砖。

| 项目 | 接地点和分层方式 |
| --- | --- |
| 地形、道路、桥面、土壤、水纹、低矮地被 | 收集过程中直接画在底层，不用植物顶端排序 |
| 建筑、独立货箱、家具 | 底部落地边缘，每个独立物体分别登记 |
| 树木 | 树干落地点；特殊北岭树使用 `baseY`，不是树冠位置 |
| 普通村民 | `actorDepth(actor)` 为 `actor.y + 22`，与人物脚底一致 |
| 阿运与货车 | `actor.y + 24`；人和推车作为一个移动单元 |
| 牛、鸡、羊、山羊 | 各自绘制函数对应的稳定脚底偏移，不能混用人物偏移 |
| 围栏 | 后排、侧面的每段、前排各自登记；前排与角色接地点相同时时序优先遮挡角色；牛舍和山羊舍接入后侧边界时，栏杆在墙边结束，不穿过门口 |
| 河流桥和西湖栈桥 | 桥面底层，后栏与前栏各自排序，走动人物处于其中 |
| 东岸菜圃 | 土壤底层；上下排植株各自登记，阿葵在中间小路上时位于两排之间 |
| 香草田 | 低矮苗床与植株底层，阿栀采摘时身体显示在植株上方 |
| 休息人物 | 休息点的坐姿接地点，和对应长椅或摇椅相邻排序 |
| 停栖猫头鹰和麻雀 | 借用所在树、井、屋顶、舞台、木柱的深度，在承载物之后绘制，显示在其前方 |
| 欢庆彩带 | 两根支柱的落地深度，绳旗先于同深度木柱绘制；高处绳旗覆盖后方舞台和水井 |
| 飞行鸟和昆虫 | `layer = 1`，不得把地面动物或普通居民放入这一层 |
| 夜灯 | 亮窗和实体灯柱属于原建筑或独立灯柱；天气层只补柔和光晕 |

采集物按各自地面接点登记，采摘人物和觅食动物的脚底位于其前方时会覆盖采集物。水中的鱼点和涟漪留在水面层；西南小湖的低矮岸边背景先画，苍鹭等生物显示在其前方。

## 新增物体的写法

```js
const site = SOME_SHARED_LAYOUT;
scenePart('new-shelter', site.bottom, () => {
  // 只绘制这个物体；不得更新路线、工作进度或资源。
  drawShelter(site);
});
```

同一个函数需要在直接预览与队列中复用时，可在入口登记，实际绘制阶段再次调用原函数：

```js
function drawShelter(site) {
  if (sceneQueue) return scenePart(`shelter:${site.id}`, site.bottom,
    () => drawShelter(site));
  // 实际像素绘制。
}
```

多个分散物体不可共用一个任意深度。先在循环内分别登记，回调使用 `let`/`const` 捕获各自坐标。若需 `ctx.translate()`，必须把 `save()`、`translate()`、实际绘制和 `restore()` 一起放进回调；不能在收集时变换、实际绘制时丢失变换。

接地点只来自世界坐标与稳定尺寸。跳跃、庆典弹跳、弯腰、摇椅摆动和翅膀扇动改变像素位置，不改变排序深度。这样动作不会使人物在建筑前后反复闪烁。

## 回归要求

修改前后关系时，执行 `node kits/farm/tests/smoke.cjs`。遮挡回归包括所有建筑和树木的前后切换、四类居民经过三种前侧围栏、阿葵上下排、西湖栈桥、彩带与水井、麻雀停井、猫头鹰停枝、绘制不修改状态以及全图 PNG。

此外检查实际画面：日常和欢庆日各一次，夜间一次；核对移动角色、暂停动作、高处停栖、道路交叉处和物体轮廓。调整坐标后同步检查命中、路线和小地图。新增物体至少补充其前后切换或附着关系的针对性验证，不能仅确认函数被调用。


## 猫屋软垫与滚动毛线球

软垫是贴地的薄物，使用地表层 `layer = -1`，避免以底边深度压住上面的球。每颗毛线球以当前 y + 5 独立排序；猫继续用 y + 9 的脚底排序，拨爪和摇尾不改变接地点。滚动位置也是悬停、点击、小地图和全图导出的实际位置；猫站在球上时优先显示猫本人。


### 东岸驴驿与花盆照料

矿坡东侧山脊各岩丘按自身底边入队，不作为画面末尾的遮罩；驴棚按棚脚，小驴按未受摆动影响的脚底 `y+14`。草场围栏拆为北侧两段、西侧各段、东侧各段与南侧前栏，北/东入口留实际开口；水槽与遮雨架为同一落地物。动物回棚后不在外墙前绘制。问候符号、耳朵与尾巴随动物绘制，暂停继续原地动作。

茶桌与椅背/椅座沿迁移后的共享坐标入队，保留座椅与人物的前后关系。花盆土壤和浇水水滴随单只花盆绘制，阿棠举起的手和小水壶随人物绘制；渲染不结算浇水或改变湿度。


阿宁喂小驴时，身体继续采用原人物脚底深度；伸出的手、胡萝卜和纸袋附着在这一绘制项里，不在场景队列末尾补画。阿宁停在东侧围栏外，小驴在门内，围栏留实际开口；小驴先走完北门出口再靠近，避免从棚屋斜穿北栏。胡萝卜木牌独立按木桩底边排序，命中也使用同一坐标。入屋休息时人物在主图、悬停和场景队列中隐藏；动物仍使用原有脚底深度和棚内隐藏规则。


溪畔浅水盘保留在巢箱的绘制项内，水量只改变盘内水面的宽度与季节颜色；不会覆盖道路或另画大片地表。白鹡鸰在试水/洗澡/晾羽时使用巢箱承载深度 `nest.y + 10`，排在盘和第三阶段小花之后；水滴、翼和尾巴附于鸟体，暂停的原地摆动不改变深度。飞来与离开才进入空中层。盘面命中仅覆盖实际水盘内侧，外沿继续显示原巢箱/养护提示，避免吞掉设施原交互。


### 驿屋暖炉与柴堆

烟囱与窗口火苗属于驿屋自身绘制项，随建筑底边排序，不整块补画到人物前面。火苗位于窗口内、窗框下，亮度只读取暖炉状态；夜间光晕沿用灯光覆盖，不附带实体。柴堆位于共享家屋坐标推导的草地，按自身 `wood.y + 3` 排序，不占村路。轻烟使用独立空中绘制项，烟囱位置仍跟随家屋；暂停时烟/火苗用视觉时间动，状态不变化。所有项都经过统一场景队列，完整 PNG 保留当前余量、炉光和烟，无新增地表覆盖。


### 蜜源花头与吸蜜蝴蝶

新花头的绘制和蝴蝶目标共用 `townNectarFlower()`，高度随植株连续生长。蝴蝶飞行使用空中层；落花吸蜜时改用对应花簇底边 `site.y + 11`，排在本花簇 `site.y + 10` 之后，翅膀、触角与吸蜜口器都附着自身绘制项。邻近树/建筑继续按接地点排序，不把停栖蝴蝶固定补画到最前面。吸蜜身体不随飞行悬浮动画偏移，暂停只合翅；实际点击和小地图采用保存的真实中心，全图 PNG 复用同一队列。


### 小驴牧草架

草架位于草场西侧，绘制深度为 `rack.y + 12`；进餐站位的小驴脚底为 `animal.y + 14`，自然排在架前，低头和嘴边草丝附在动物自身绘制项内。普通散步的西界为架子留出身体空间。前侧围栏仍在更南的接地点，不为进餐把整只小驴固定补画到最前面；牧草堆只改变架内高度，暂停的嘴/耳/头部动作不改变脚底或场景深度。主图、点击、小地图和完整 PNG 均从共享草场/草架坐标取值。

### 人物的布伞和货车挂钩

布伞属于人物附着物，阿棠在 `town-traveller`、阿宁在 `village-walker` 原项中绘制；伞面高度、伞沿摆动或开合都不改变人物脚底深度，也不登记空中/最前层。伞骨、手柄和握住柄的手随人物一起，树木/房屋遮挡仍取决于人物实际接地点。只在真实可见且户外时显示；回屋后不留下独立悬空伞。

折伞画在原 `traveller-cart` 项内，挂钩位置等于实时货车位置加共享偏移；人物使用后的空挂钩继续附于车身。命中范围包含伞沿一像素摆动，同一伞面点击回到对应人物；挂钩点击只换配色。普通图、纯享与全图 PNG 共用这些函数，不额外在夜景补画。

### 人物写生与车前书册

膝上的画页、握页手、铅笔附于阿棠原 `town-traveller` 绘制项，接地点仍为 `actorDepth(actor)`，不因坐姿、笔尖摆动或画的进度改变，也不新增空中/最前层。写生期间杯子先放下，美术不同时画持杯与执笔，但既有一次取茶记录保持。收起的画册附于原 `traveller-cart` 项，以 `townCartPosition()` 加共用偏移取位置，推车进出时跟车走；写生时车前不重复画一本。

主图与完整 PNG 复用同一画页函数；实际书册位置用于命中。小地图纸页只跟随真实阿棠的接地点，不加大块背景。UI 预览 Canvas 单独接收 context，不能改主图绘制状态或生成随机图案。季节快照仅属于保存的画页，原世界季节仍按连续过渡运行。

## 猫咪一起歇脚

作伴沿用两个独立 `plaza-cat:名字` 项与 y + 9 接地点，等待、洗脸、蜷睡都不新增前层或合并大区域。姿态从保存的计划只读推导，面对同伴也不改变排序。两席分开 56 像素、两路互留通道；猫在长椅/木台/水井附近仍按实际脚底前后排序，鼠标提示和小地图使用原实际位置。全图导出同一绘制函数，暂停洗脸/摆尾读取显示时钟，不推进计划。

## 屋檐麻雀与抬头的阿宁

第二间村民小屋的两个檐点由共享房屋坐标生成。停檐麻雀仍使用原 `plaza-sparrow:索引` 项，承载深度为小屋 y + 117，紧随房屋 y + 116；视觉鸟身在屋顶，不能按屋顶高度排序而被自己的屋子遮住。飞行复用原空中层，落檐后 lift 为零；不追加一个前景复制鸟。鼠标与小地图读取原麻雀真实位置，完整 PNG 复用同一队列。

### 已建道路的草地过渡

施工的 32 像素分段只决定开放进度，不应成为可见地砖。道路绘制取所有已建路段的并集，外沿恢复原先约 3–7 像素的不规则半透明草地过渡。同一边缘像素只合成一次，交叉口、相邻路段和桥面内部没有晕边；河水范围不画土色过渡。路面细粒使用世界坐标布置，不在每段起点重新排列。仅道路图变化时重建绘制几何缓存，主图和完整 PNG 共用此画法，绘制不改变施工或存档状态。

路面必须将所有土路矩形加入同一个 Canvas 路径，整体填色一次；不能逐段调用 `fillRect`，否则非整数缩放时抗锯齿会显出内部接缝。两种透明度的外沿也各自合并成一个路径填色，避免单像素行在缩放后形成细线。使用默认非零填充规则保留重叠交叉口。

启用村庄建设时，主场院落、鸡舍连接路与偏远道路都由同一份 `VILLAGE_ROADS` 绘制；旧 `pathTile` 不能同时补画，果园踏脚石仍独立保留。小地图同样读取已建道路图，不能再叠加固定主场或村口路面。连接现有道路时复用其位置和宽度，不在同一通道上下错开铺两条平行路；施工队小屋从菜圃南侧的主路直接转向南进入。
